## Overview

The WingDrive daemon and CLI can be deployed on Linux systems in several ways:
- **Docker** - Recommended for easy deployment and isolation
- **Native binaries** - The `.deb` or AUR package, or the `wing-server` release archive, on TrueNAS SCALE and other x86_64 Linux systems
- **Systemd service** - Auto-start on boot with native binaries

## Docker Deployment

### Prerequisites

- Docker 20.10+ or Docker Engine
- Docker Compose (optional, but recommended)

### Quick Start with Docker Compose

1. **Create docker-compose.yml**:

```yaml
version: '3.8'

services:
  wingdrive:
    image: wingdrive:latest
    container_name: wingdrive-daemon
    restart: unless-stopped
    volumes:
      - wingdrive-data:/data
      # Mount directories to index
      - /path/to/your/files:/mnt/files:ro
    environment:
      - WINGDRIVE_DATA_DIR=/data

volumes:
  wingdrive-data:
```

2. **Build and start**:

```bash
# Build the image
docker compose build

# Start the daemon
docker compose up -d

# View logs
docker compose logs -f
```

### Docker CLI Commands

```bash
# Build image
docker build -t wingdrive:latest .

# Run daemon
docker run -d \
  --name wingdrive-daemon \
  --restart unless-stopped \
  -v wingdrive-data:/data \
  -v /path/to/files:/mnt/files:ro \
  wingdrive:latest

# View status
docker exec wingdrive-daemon wing status

# View logs
docker logs -f wingdrive-daemon

# Execute CLI commands
docker exec wingdrive-daemon wing library list
```

### Multi-Architecture Support

The Dockerfile supports both x86_64 and ARM64:

```bash
# Build for ARM64 (Raspberry Pi)
docker build --platform linux/arm64 -t wingdrive:arm64 .

# Build for x86_64 (servers, TrueNAS)
docker build --platform linux/amd64 -t wingdrive:amd64 .

# Build multi-arch with buildx
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t wingdrive:latest \
  --push .
```

## Native Binary Deployment

### Installation

Releases ship native binaries for Linux x86_64 only. On ARM64 (Raspberry Pi), use the Docker image
or build from source.

- **`wing` and `wing-daemon`:** the `.deb` (`sudo apt install ./WingDrive-<version>-amd64.deb`)
  installs both in `/usr/bin` with the desktop app. On Arch, `wingdrive-bin` puts them in
  `/opt/wingdrive/usr/bin` and links `/usr/bin/wing`.
- **`wing-server` and `wing`, no desktop app:** the `wing-server-<version>-linux-x86_64` archive.
  `wing-server` runs the daemon and the web interface in one process; see
  [Self-hosting](../overview/self-hosting.mdx).
- **From source:** `cargo build --release --bin wing --bin wing-daemon`, then copy both from
  `target/release/` to `/usr/local/bin`. `wing start` looks for `wing-daemon` next to `wing`.

```bash
# Verify a downloaded release file
sha256sum -c SHA256SUMS --ignore-missing

# Test installation
wing --version
```

### Running the Daemon

```bash
# Start in foreground (for testing)
wing start --foreground

# Start in background
wing start

# Check status
wing status

# Stop daemon
wing stop
```

## Systemd Service (Auto-Start)

### Installation

The CLI includes built-in systemd service management:

```bash
# Install and enable auto-start
wing daemon install

# Check status
wing daemon status

# Uninstall auto-start
wing daemon uninstall
```

The installer quotes the daemon executable and data directory for systemd. Paths containing
spaces, double quotes, percent signs or dollar signs keep their original values.
For an existing installation with a malformed unit, rerun `wing daemon install` with its
original data directory and instance to regenerate the unit.

This creates a systemd user service at:
```
~/.config/systemd/user/wingdrive-daemon.service
```

### Manual Systemd Setup

If you prefer manual setup, create the service file:

```bash
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/wingdrive-daemon.service << 'EOF'
[Unit]
Description=WingDrive Daemon
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/wing-daemon --data-dir %h/.local/share/wingdrive
Restart=on-failure
RestartSec=5s
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=default.target
EOF
```

Then enable and start:

```bash
# Reload systemd
systemctl --user daemon-reload

# Enable auto-start
systemctl --user enable wingdrive-daemon

# Start now
systemctl --user start wingdrive-daemon

# Check status
systemctl --user status wingdrive-daemon

# View logs
journalctl --user -u wingdrive-daemon -f
```

## TrueNAS Deployment

### TrueNAS SCALE (Debian-based)

TrueNAS SCALE supports Docker, so you can use either method:

#### Option 1: Docker (Recommended)

1. Enable Docker/Kubernetes in TrueNAS SCALE Apps
2. Deploy using the docker-compose.yml above
3. Mount your TrueNAS pools as volumes

#### Option 2: Native Binary

```bash
# SSH into TrueNAS
ssh admin@truenas

# Install wing and wing-daemon (built from source, see Native Binary Deployment)
sudo install -m 755 wing wing-daemon /usr/local/bin/

# Set up systemd service
wing daemon install

# Index your pools
wing location add /mnt/pool1
wing location add /mnt/pool2
```

### TrueNAS CORE (FreeBSD)

Currently unsupported. Use TrueNAS SCALE (recommended) or run in a Linux VM.

## Raspberry Pi Deployment

### Prerequisites

- Raspberry Pi 3/4/5 or newer
- Raspberry Pi OS (64-bit recommended)
- At least 1GB free RAM

### Installation

```bash
# Update system
sudo apt-get update && sudo apt-get upgrade -y

# No ARM64 release binaries: build on the Pi (or cross-compile) from a source checkout
cargo build --release --bin wing --bin wing-daemon

# Install
sudo install -m 755 target/release/wing target/release/wing-daemon /usr/local/bin/

# Install auto-start
wing daemon install

# Start daemon
sudo systemctl --user start wingdrive-daemon
```

### Performance Tips

- Use external SSD for better I/O performance
- Limit concurrent indexing jobs: `wing config set jobs.max_concurrent 2`
- Disable thumbnail generation for large libraries to save RAM

## Configuration

### Data Directory

By default, data is stored at:
- Native: `~/.local/share/wingdrive` (Linux)
- Docker: `/data` (mapped to volume)

Override with `--data-dir` flag:

```bash
wing --data-dir /mnt/external/wingdrive start
```

### Updates

```bash
# Check for a newer release and print how to install it
wing update
```

`wing update` never replaces binaries. Update a packaged install through its
package manager, and a source build by checking out the new tag and rebuilding. When the daemon is
running, `wing update` also lists the installed adapters that have an update or a revoked version,
as `wing adapters outdated` does; install them with `wing adapters update --all`.

### Multiple Instances

Run multiple daemon instances:

```bash
# Instance for work files
wing --instance work --data-dir ~/wingdrive-work start

# Instance for personal files
wing --instance personal --data-dir ~/wingdrive-personal start

# Install both as services
wing --instance work daemon install
wing --instance personal daemon install
```

## Troubleshooting

### Daemon Won't Start

```bash
# Check logs
journalctl --user -u wingdrive-daemon -n 50

# Or with CLI
wing logs follow

# Reset data and restart
wing restart --reset
```

### Permission Issues

```bash
# Fix binary permissions
sudo chmod +x /usr/local/bin/wing /usr/local/bin/wing-daemon

# Fix data directory permissions
chmod -R u+rw ~/.local/share/wingdrive
```

### Port Conflicts

If you see "address already in use":

```bash
# Check what's using the socket
lsof ~/.local/share/wingdrive/daemon/daemon.sock

# Kill old process
pkill wing-daemon

# Restart
wing start
```

### Out of Memory (Raspberry Pi)

```bash
# Check available memory
free -h

# Reduce concurrent jobs
wing config set jobs.max_concurrent 1

# Restart daemon
wing restart
```

## Security Considerations

### Running as Non-Root

Always run as a regular user, never as root:

```bash
# DON'T do this
sudo wing start  # ❌

# DO this instead
wing start  # ✓
```

### Firewall Configuration

If enabling API access (future):

```bash
# Allow specific port
sudo ufw allow 8080/tcp

# Or limit to local network
sudo ufw allow from 192.168.1.0/24 to any port 8080
```

### File Permissions

Ensure indexed directories are readable:

```bash
# Check permissions
ls -la /path/to/index

# Fix if needed
chmod -R u+r /path/to/index
```

## Uninstallation

### Remove Daemon

```bash
# Stop daemon
wing stop

# Remove auto-start
wing daemon uninstall

# Remove binaries
sudo rm /usr/local/bin/wing /usr/local/bin/wing-daemon

# Remove data (optional)
rm -rf ~/.local/share/wingdrive
```

### Remove Docker

```bash
# Stop and remove container
docker compose down

# Remove volumes
docker volume rm wingdrive-data

# Remove image
docker rmi wingdrive:latest
```

## Advanced Configuration

### Custom Systemd Service Options

Edit `~/.config/systemd/user/wingdrive-daemon.service`:

```ini
[Service]
# Limit memory usage
MemoryMax=1G

# Set nice priority
Nice=10

# Set I/O priority
IOSchedulingClass=best-effort
IOSchedulingPriority=5

# Environment variables
Environment="RUST_LOG=info"
```

Then reload and restart:

```bash
systemctl --user daemon-reload
systemctl --user restart wingdrive-daemon
```

### Docker Resource Limits

In docker-compose.yml:

```yaml
services:
  wingdrive:
    # ... other config ...
    deploy:
      resources:
        limits:
          cpus: '2.0'
          memory: 2G
        reservations:
          memory: 512M
```
