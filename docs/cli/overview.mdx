# WingDrive CLI

A comprehensive command-line interface for managing WingDrive Core with full daemon architecture, real-time monitoring, and cross-device file management.

## Features

- **️ Daemon Architecture**: Background daemon with client-server communication
- **Library Management**: Create, open, switch, and manage multiple libraries
- **Location Management**: Add, remove, and monitor indexed locations with real-time watching
- **️ Job Management**: View, monitor, and control background jobs with live progress
- **Real-time Monitoring**: Beautiful TUI for monitoring job progress and system events
- **Indexing Control**: Start indexing jobs with different modes (shallow/content/deep)
- **Networking Support**: Device pairing, file sharing via Spacedrop
- **Multiple Instances**: Run isolated daemon instances for different use cases
- **Comprehensive Logging**: Built-in logging with file output for debugging
- **️ Cross-platform**: Works on macOS, Linux, and Windows
- **Rich UI**: Colored output, progress bars, and formatted tables

### New Modular Architecture Benefits

The refactored daemon architecture provides:

- **Maintainability**: Each domain (library, location, job, etc.) is isolated in its own handler module
- **Extensibility**: New commands can be added by simply creating a new handler
- **Type Safety**: All commands and responses are strongly typed
- **Code Organization**: Clear separation between command handling, business logic, and transport
- **Testability**: Individual handlers can be unit tested in isolation
- **Performance**: Efficient command routing through handler registry

## Installation

```bash
# Build the CLI
cargo build --release --package wing --package wing-core

# Or build just the CLI for development
cd apps/cli && cargo build

# Install globally (optional)
cargo install --path apps/cli
```

The binary is already called `wing`; you can also alias it.

Example:
```bash
# For release build
echo 'alias wing="/path/to/wingdrive/target/release/wing"' >> ~/.zshrc

# For debug build (faster compilation)
echo 'alias wing="/path/to/wingdrive/target/debug/wing"' >> ~/.zshrc

# Reload your shell configuration
source ~/.zshrc
```

## Quick Start

```bash
# Start the WingDrive daemon
wing start

# Create a library and add a location
wing library create "Personal"
wing location add ~/Desktop --name "Desktop"

# Monitor indexing progress
wing job monitor

# Check system status
wing status
```

**Note**: If you haven't set up the alias, use `./target/debug/wing` or `./target/release/wing` instead of `wing`.

## Usage

### Daemon Management

```bash
# Start daemon in background
wing start

# Start daemon with networking enabled
wing start

# Start daemon in foreground (for debugging)
wing start --foreground

# Stop the daemon
wing stop

# Check daemon status
wing status
```

### Daemon Auto-Start (macOS)

Set up the daemon to start automatically on login:

```bash
# Install auto-start service
wing daemon install

# Check installation status
wing daemon status

# Remove auto-start service
wing daemon uninstall
```

The install command creates a LaunchAgent that starts the daemon on login and restarts it if it crashes. Logs write to your data directory at `~/Library/Application Support/wingdrive/logs/`. This works with multiple instances by passing `--instance` before the daemon command.

<Note>
Auto-start is currently macOS-only. Linux systemd support is planned.
</Note>

### Multiple Daemon Instances

The CLI supports running multiple isolated daemon instances:

```bash
# Run a separate daemon instance
sd --instance test start
sd --instance test library create "Test Library"

# Stop specific instance
sd --instance test stop

# Install auto-start for specific instance
sd --instance test daemon install
```

### Basic Commands

```bash
# Show help
wing --help

# Enable verbose logging
sd -v <command>

# Use custom data directory
sd --data-dir /path/to/data <command>
```

### Library Management

```bash
# Create a new library
wing library create "My Library"
wing library create "My Library" --path /custom/path

# List all libraries
wing library list

# Open an existing library
wing library open /path/to/library

# Switch to a library by name or ID
wing library switch "My Library"
wing library switch 12345678-1234-1234-1234-123456789012

# Show current library
wing library current

# Close current library
wing library close
```

### Location Management

```bash
# Add a location to index (automatically starts watching)
wing location add ~/Documents
wing location add ~/Pictures --name "My Photos" --mode deep

# List all locations with status
wing location list

# Remove a location (stops watching and indexing)
wing location remove <location-id>

# Rescan a location (triggers re-indexing)
wing location rescan <location-id>
wing location rescan <location-id> --force  # Full rescan, ignore change detection
```

**Note**: Location IDs are UUIDs displayed in the list command. All location operations work with the daemon automatically.

### Enhanced Indexing

The new indexing system supports different scopes and persistence modes:

```bash
# Quick scan of current directory only (no subdirectories)
wing index quick-scan /path/to/directory --scope current

# Quick scan with ephemeral mode (no database writes)
wing index quick-scan /path/to/directory --scope current --ephemeral

# Browse external paths without adding to managed locations
wing index browse /media/external-drive --scope current
wing index browse /network/drive --scope recursive --content

# Index managed locations with specific scope
wing index location /managed/location --scope current --mode shallow
wing index location <location-uuid> --scope recursive --mode deep

# Legacy full location indexing (backward compatibility)
wing scan /path/to/directory --mode content --watch
```

**Index Scopes:**
- `current`: Index only the specified directory (single level)
- `recursive`: Index the directory and all subdirectories

**Index Modes:**
- `shallow`: Metadata only (fastest)
- `content`: Metadata + content hashing (moderate)
- `deep`: Full analysis including media metadata (slowest)

**Use Cases:**
- **UI Navigation**: `quick-scan --scope current` for instant directory viewing
- **External Browsing**: `browse --ephemeral` for exploring non-managed paths
- **Location Updates**: `location --scope current` to refresh specific directories

### Job Management

```bash
# List all jobs with colored status and progress
wing job list
wing job list --status running      # Filter by status

# Show detailed job information
wing job info <job-id>

# Monitor jobs in real-time with live progress bars
wing job monitor
wing job monitor --job-id <job-id>  # Monitor specific job

# Control jobs (planned features)
wing job pause <job-id>
wing job resume <job-id>
wing job cancel <job-id>
```

**Job Monitor Features:**
- Live progress bars for running jobs
- Color-coded status (running: yellow, completed: green, failed: red)
- ️ Real-time updates every second
- Automatic cleanup of completed jobs
- ️ Ctrl+C to exit gracefully

### File Operations

```bash
# Copy files with progress tracking
wing file copy ~/source.txt ~/destination.txt
wing file copy ~/Photos/*.jpg ~/Backup/ --verify

# Move files
wing file move ~/Downloads/*.pdf ~/Documents/ --preserve-timestamps

# Advanced copy options
wing file copy ~/Project/ ~/Backup/Project/ \
  --overwrite \
  --verify \
  --preserve-timestamps
```

### System Commands

```bash
# Show system status
wing status

# Monitor all system activity (TUI)
wing monitor

# View daemon logs
wing system logs
wing system logs --tail 50
```

### Networking & Device Management

```bash
# Initialize networking (if daemon wasn't started with)
wing network init

# Start/stop networking
wing network start
wing network stop

# List connected devices
wing network devices

# Device pairing
wing network pair --initiate              # Generate pairing code
wing network pair --join <code>           # Join using code
wing network pair --status                # Check pairing status

# Spacedrop (file sharing)
wing network spacedrop <device-id> /path/to/file --sender "Your Name"

# Remove paired device
wing network revoke <device-id>
```

## Examples

### Complete Workflow

```bash
# 1. Start the daemon
wing start

# 2. Create a library
wing library create "Personal"

# 3. Add locations with different index modes
wing location add ~/Desktop --name "Desktop" --mode content
wing location add ~/Documents --name "Documents" --mode content
wing location add ~/Pictures --name "Photos" --mode deep

# 4. Add cloud storage
wing volume add-cloud "S3 Backup" --service s3 --bucket my-backup --region us-west-2

# 5. Monitor the indexing progress
wing job monitor

# 6. Copy files to cloud using unified URIs
wing cp local://macbook/Desktop/important.pdf s3://my-backup/documents/

# 7. Check the results
wing location list
wing job list
```

### Multiple Libraries

```bash
wing library create "Work"

```

```bash
# Index multiple locations
wing location add ~/Documents --name "Docs"

wing location add ~/Downloads --name "Downloads" --mode shallow
wing job list --status running
```

## Architecture

The CLI follows a modular architecture with clear separation of concerns:

- **Client**: Lightweight CLI that communicates with daemon
- **Daemon**: Long-running background service managing Core
- **Handlers**: Modular command processors for each domain
- **Transport**: JSON-RPC communication over Unix socket
- **Core**: WingDrive Core library for all operations

### Benefits

1. **Performance**: Daemon keeps Core loaded in memory
2. **Persistence**: Operations continue after CLI exits
3. **Concurrency**: Multiple CLI clients can connect
4. **Monitoring**: Real-time tracking of background tasks
5. **Isolation**: Multiple instances for testing
