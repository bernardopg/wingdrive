# Multi-Instance Daemon Support

WingDrive CLI now supports running multiple daemon instances simultaneously, enabling local testing of device pairing and other multi-device features.

## Overview

Multiple daemon instances allow you to:
- Test device pairing locally by running two instances
- Simulate multi-device scenarios on a single machine
- Isolate different development/testing environments
- Run production and development daemons side-by-side

## Usage

### Starting Multiple Instances

```bash
# Start default instance
wingdrive-cli start

# Start named instances
wingdrive-cli start --instance alice
wingdrive-cli start --instance bob

# Start with networking enabled
wingdrive-cli start --instance alice
wingdrive-cli start --instance bob
```

### Targeting Specific Instances

Use the `--instance` flag to target commands to specific daemon instances:

```bash
# Default instance
wingdrive-cli library list

# Named instances
wingdrive-cli --instance alice library list
wingdrive-cli --instance bob library create "Bob's Library"
```

### Instance Management

```bash
# List all daemon instances
wingdrive-cli instance list

# Stop specific instance
wingdrive-cli instance stop alice
wingdrive-cli --instance bob stop  # Alternative syntax

# Check status of specific instance
wingdrive-cli --instance alice daemon
```

### Auto-Start Configuration

On macOS, you can configure instances to start automatically on login:

```bash
# Install auto-start for default instance
wingdrive-cli daemon install

# Install auto-start for named instance
wingdrive-cli --instance alice daemon install

# Check auto-start status
wingdrive-cli --instance alice daemon status

# Remove auto-start
wingdrive-cli --instance alice daemon uninstall
```

Each instance gets its own LaunchAgent plist file. The daemon starts with the correct `--data-dir` and `--instance` flags automatically. Logs write to `~/Library/Application Support/wingdrive/logs/daemon.out.log` and `daemon.err.log`.

### Device Pairing Example

Test device pairing locally using two instances:

```bash
# Terminal 1: Start Alice's daemon
wingdrive-cli start --instance alice --foreground

# Terminal 2: Start Bob's daemon
wingdrive-cli start --instance bob --foreground

# Terminal 3: Alice generates pairing code
wingdrive-cli --instance alice network init --password "test123"
wingdrive-cli --instance alice network pair generate --auto-accept

# Terminal 4: Bob joins using Alice's code
wingdrive-cli --instance bob network init --password "test123"
wingdrive-cli --instance bob network pair join "word1 word2 word3 ... word12"
```

## Architecture

### Instance Isolation

Each instance has completely isolated:

- **Socket paths**: `wingdrive.sock`, `wingdrive-alice.sock`, `wingdrive-bob.sock`
- **PID files**: `wingdrive.pid`, `wingdrive-alice.pid`, `wingdrive-bob.pid`
- **Data directories**: `data/sd-cli-data/`, `data/sd-cli-data/instance-alice/`
- **CLI state**: Separate `cli_state.json` per instance

### File Structure

```
$runtime_dir/               # /tmp or $XDG_RUNTIME_DIR
├── wingdrive.sock         # Default instance socket
├── wingdrive.pid          # Default instance PID
├── wingdrive-alice.sock   # Alice instance socket
├── wingdrive-alice.pid    # Alice instance PID
├── wingdrive-bob.sock     # Bob instance socket
└── wingdrive-bob.pid      # Bob instance PID

data/sd-cli-data/                    # Default instance data
├── wingdrive.json
├── libraries/
└── cli_state.json

data/sd-cli-data/instance-alice/     # Alice instance data
├── wingdrive.json
├── libraries/
└── cli_state.json

data/sd-cli-data/instance-bob/       # Bob instance data
├── wingdrive.json
├── libraries/
└── cli_state.json
```

## Development Workflow

### Testing Pairing Protocol

```bash
# Start two instances for pairing test
wingdrive-cli start --instance initiator --foreground &
wingdrive-cli start --instance joiner --foreground &

# Initialize networking
wingdrive-cli --instance initiator network init --password "dev123"
wingdrive-cli --instance joiner network init --password "dev123"

# Test pairing
CODE=$(wingdrive-cli --instance initiator network pair generate --auto-accept | grep "Pairing code:" | cut -d' ' -f3-)
wingdrive-cli --instance joiner network pair join "$CODE"

# Verify connection
wingdrive-cli --instance initiator network devices
wingdrive-cli --instance joiner network devices
```

### Instance Cleanup

```bash
# Stop all instances
wingdrive-cli instance list
wingdrive-cli instance stop alice
wingdrive-cli instance stop bob
wingdrive stop  # Default instance

# Clean up sockets (if needed)
rm /tmp/wingdrive*.sock /tmp/wingdrive*.pid
```

## Backwards Compatibility

The implementation maintains full backwards compatibility:
- All existing commands work unchanged with the default instance
- No breaking changes to CLI interface
- Default instance behavior is identical to single-instance mode

## Implementation Notes

- Instance names must be valid filenames (no special characters)
- Socket discovery happens automatically via filesystem scanning
- Daemon startup checks for instance conflicts
- Each instance runs independently with separate process trees
