# Sprint S06 — 2026-11-26 to 2026-12-09

Milestones: **M3** (Cross-platform desktop and release) and **M5** (cloud integrations, an exception
the author decided on 2026-11-12)

**Goal:** the installed desktop app updates itself from signed releases, the Explorer is tested end
to end on every pull request, Windows passes the TAURI-012 matrix by hand, and any user connects
Google Drive and Google Photos by signing in.

## Commitment

Ordered by value. INTG-001 to INTG-003 depend on the author's Google account (project, domain,
verification), and Google's verification can take weeks; INTG-004 closes only after them. What does
not depend on the author (INTG-005) runs in parallel.

Order decided on 2026-11-15: the desktop comes before the integrations. The signed updater brings
each fix to existing installs, and TAURI-018 catches on the pull request the kind of failure that
CORE-021 only showed on the tag. TAURI-012 depends on the author on a Windows machine; without a Mac,
the macOS round moves to S07 and M3 closes only after it.

Outside the commitment, in the M5 backlog under epic INTG-000: INTG-006 to INTG-009 (Google on a
remote wing-server and on mobile, shared drives, change feed, Photos albums), INTG-020 (provider
framework) and the providers INTG-021 to INTG-031 (Dropbox, OneDrive, Nextcloud, WebDAV, iCloud
Drive, Box, pCloud, MEGA, Proton Drive, object storage, SFTP and SMB).

### Decision pending from the author

INTG-003 depends on the Drive scope. `drive` (what CLOUD-004 uses today) is restricted: it needs
verification and a yearly CASA security assessment. `drive.file` skips the assessment, but WingDrive
would only see files it created or that the user opens through the Google Picker, so browsing the
whole Drive and syncing existing folders would stop working.
